# 夜航 v0.1.5 维护与验证说明

日期：2026-10-07。实现目录：`../chatgpt-nebula-extension`。本文件区分工程事实、实际测试和仍需真人网页确认的部分。

## 架构与修改边界

网页内容脚本在隔离执行环境中给 `html` 添加三项前缀属性和五项前缀 CSS 变量，并在 `body` 下放入独立扩展 iframe。iframe 使用扩展自己的脚本、样式和媒体存储。内容脚本不读取会话，不修改编辑器、React 状态或网页接口。

JavaScript 隔离不能隔离 DOM 和 CSS；网页适配仍依赖 DOM 语义标记和颜色变量。该机制由 [Chrome 内容脚本文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) 描述。网页改变后，优先检查 `styles/site.css`，避免把修改扩展到数据接口或聊天行为。

背景层固定铺满视口，点击穿透、不可聚焦。只监听 `body` 和 `html` 的直接子节点变化，节流重建被删除的 iframe；不扫描整棵对话 DOM。停用时撤销插件自己的属性、内联变量和 iframe。页面从缓存恢复时重新读取配置，媒体地址按需要重建。

`soft` 是轻量模式，`glass` 是通透模式。菜单、对话框、警告框和列表框保持实色表面，避免透明层叠造成文字难辨。不要为了扩大透明范围加入无条件全站 `* { background: transparent }`。

## 网页样式适配与 0.1.2 布局修正

0.1.1 处理左侧栏与 Work 输入区的灰底，但复用了站点的样式层名称，引入了间距和居中失效的回归。0.1.2 改用独有层、取消侧栏/顶部布局外壳直接模糊，并恢复用户底栏的实底。修改集中在 `styles/site.css`；机制和对照证据见 `布局偏差调查与修复.md`。截图没有包含真实 DOM 或计算样式，语义挂钩仍来自第三方项目观察，不是官方稳定接口。

- **新旧颜色变量**：同时维护 `--main-surface-*`、`--sidebar-surface-*`、`--composer-surface-*` 等已有别名，以及 `--color-surface`、`--color-surface-secondary`、`--color-background-panel`、`--color-background-composer-primary` 等新别名。实际外壳另有受控透明底色，避免只改未被当前节点消费的变量。
- **局部主题**：规则覆盖 `html`、`body` 及识别到的 `data-theme` / `.dark` / `.light` 作用域，避免内部主题重置继承颜色；保护区内部的局部主题仍使用清晰表面。
- **侧栏边界**：以明确 ID、test-id 和 `aside.app-shell-left-panel` 等语义节点识别左侧栏，清理导航表面的重复实底，保留用户底栏实底、选中、悬停与按钮颜色。用户区候选限于 footer、明确底部标记、滚动区紧邻含菜单按钮的节点、profile 按钮直接父级；不把任意含 profile 的祖先整块上色。
- **输入区单层着色**：区分表单布局外壳与实际输入表面，只在识别的表面保留一层可调透明底色；内部编辑器和工具条不再重复叠底。该规则只改变样式，不写入编辑器内容、发送状态或组件状态。
- **弹层保护**：对话框、警告框、菜单、列表框及已识别 Radix 弹层包装区域保持清晰表面，透明规则排除这些区域及其后代。新增选择器时应继续检查保护区，而不是只检验首页。
- **CSS 分层**：全部网页规则使用独有的 `nebula-skin` 层，不声明站点的 `utilities`、`base` 等层名。Chrome 静态 CSS 在 DOM 构造前注入，`run_at` 仅控制 JavaScript；提前使用宿主层名即使选择器不匹配也会改变首次层注册顺序。[Chrome 注入时机](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[W3C 层排序](https://www.w3.org/TR/css-cascade-5/#layer-order)。独有层的重要声明仍不能保证覆盖内联重要声明或其他更早扩展层。
- **定位与模糊**：侧栏与顶部布局外壳不新增 `backdrop-filter`，保留原生 fixed/absolute 后代的定位参照。输入表面仍使用模糊；若以后发现其内部定位内容回归，应在实际 DOM 上确认，不以调整宽度掩盖包含块问题。[CSSWG Filter Effects 2 草案](https://drafts.csswg.org/filter-effects-2/#BackdropFilterProperty) 与本次 Chrome 实验详见布局调查。

代码注释说明选择器边界和层排序原因；新增兼容规则也应保留中文注释。网页再次变动时，先核对实际使用的表面变量、局部主题及外壳，避免扩大到聊天接口或重写整套媒体实现。

## 输入表面与背景预设

0.1.3 将输入绘制分为明确表面、已识别输入容器内的旧语义表面和 fallback，候选只取包含编辑器的实际表面，外表单清底。`composer-visual-smoke.cjs` 对无扩展原生基线测量四角、几何、描边、模糊、焦点、附件和停用恢复。完全没有已知语义标记的内层仍可能未识别，不能将“布局检查通过”解释为黑底已经消除。完整说明见 `输入框与线框蓝光说明.md`。

「线框蓝光」使用本包图片以及背景 iframe 内的 CSS 光束、网格和稀疏字符。`wireframe-preset-smoke.cjs` 检查一键设置、原素材保留、动态/减少动态、独立编辑器范围、资源失败回退、预览点击与窄屏。普通预设按钮只换背景，一键按钮明确应用整套外观，不改启停和动态选择；自定义素材不继承该预设光效或专属遮罩。素材提示词见 `线框蓝光素材生成记录.md`。

0.1.4 增加 `portraitCycle` 布尔配置，默认 `false`。旧配置没有该字段时，规范化结果保持静态线框；普通预设按钮不打开人物切换。一键原版风格按钮明确设为 `true`，但保留启停、总动态开关和已保存素材。人物切换只有在线框预设、皮肤启用、两个动态开关开启且系统没有减少动态时才启用。网页样式和 `content.js` 本轮沿用 0.1.3，变动集中于背景、设置与本包素材。

背景使用固定线框底图和有色叠层，同用焦点与 `object-fit: cover`；底图在过渡期间保持可见。第二张图按需解码，两张图解码成功且自然尺寸相同后才开启固定 10 秒的透明度动画。`decode()` 返回可等待的解码结果；本项目另外检查两图尺寸、请求代次和当前启用条件，避免旧的异步完成回调恢复已经关闭的叠层。[WHATWG HTML Living Standard：`HTMLImageElement.decode()`](https://html.spec.whatwg.org/multipage/embedded-content.html#dom-img-decode)（核查于 2026-10-07）。

后台可见性变化只暂停已经运行的动画，保留相位；关闭人物切换、关闭总动态、系统减少动态、换背景或页面退出时解除叠层并重置。CSS 的 `animation-play-state: paused` 保持当前进度，恢复时继续；引用文档是 **2023-03-02 的 W3C Working Draft**，不能将其标为已发布 Recommendation。[CSS Animations Level 1 § 3.7](https://www.w3.org/TR/css-animations-1/#animation-play-state)（核查于 2026-10-07）。

有色图失败或尺寸不一致时只关闭人物叠化，保留线框、蓝光与代码雨；线框底图本身失败仍按原流程回退极光。关闭人物切换会退出失败状态，重新开启可重新尝试。所有图像都在扩展包内，运行时没有生成模型调用、远程图片、计时器逐帧换图或会话触发动作。完整行为和素材记录见 `人物双态背景说明-0.1.4.md`、`人物双态素材生成记录-0.1.4.md`。

## manifest 字段说明

| 字段 | 本项目声明 | 目的 |
| --- | --- | --- |
| `manifest_version` | 3 | 使用 Manifest V3 扩展结构 |
| `version` | 0.1.5 | 本次运行包版本 |
| `minimum_chrome_version` | 115 | 与本方案采用的存储规则范围一致，不等于全部版本都已实测 |
| `permissions` | `storage` | 本机设置及状态保存 |
| `content_scripts.matches` | `https://chatgpt.com/*` | 仅在指定网站顶层页注入 |
| `world` / `all_frames` | `ISOLATED` / `false` | 隔离脚本变量；不向所有网页子 iframe 注入 |
| `action` | `popup.html` | 快捷开关 |
| `options_ui` | `options.html`，独立标签页 | 完整设置、媒体选择、预览 |
| `web_accessible_resources` | 仅 `backdrop.html`，只开放到 ChatGPT | 允许内容脚本挂载扩展背景入口 |
| `content_security_policy` | 本机脚本、本机或 Blob 媒体，禁止网络连接 | 不执行外部脚本，不加载远程素材 |

策略适用于扩展页面及其 iframe，官方机制见 [Chrome 扩展 CSP 文档](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy)。这里允许内联**样式**供滑块动态设置外观，脚本仍仅来自本包文件。

## 本机存储与并发

`nebulaSettings` 存入 `chrome.storage.local`。规范化函数限制数值范围、枚举和颜色格式，并丢弃未知字段。设置页与弹窗使用同一个扩展源的 Web Locks，把读取、合并、保存纳入串行过程，降低同时操作时互相覆盖的风险。

媒体存入扩展源 IndexedDB 的 `nebulaMedia / assets / asset`，只保留当前一份素材及静态封面。成功解码并生成封面后才覆盖记录，单文件上限是本产品的 50 MiB 限制。`chrome.storage.local` 的默认配额和异步使用方式见 [Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)；大媒体没有放入该设置存储。

素材版本单调增加。清除操作在同一 IndexedDB 事务内检查用户确认的版本；版本变化则保留新文件并提示重新查看。恢复默认仅重置设置，保留媒体。不要绕过设置页确认入口去执行清除。

视频关闭动态时暂停，GIF 切换到生成的静态封面并解除原图片地址。切换素材和退出时释放 Blob 地址。背景读取或解码失败回退预设；自动播放失败保留可见静态帧；素材导入或存储失败保留原素材。对应失败会显示提示，回退状态不是网页选择器兼容性诊断。

## 验证证据与限制

原有浏览器验证脚本：`../chatgpt-nebula-extension/tests/browser-smoke.cjs`，机器可读结果为相邻 `results-latest.json`。它覆盖扩展加载、设置、媒体、交互和清理。新增 `work-style-smoke.cjs` 使用 `fixtures/chatgpt-work.html` 检查侧栏、输入表面、工具条、局部主题及分层样式；修复前后结果分别为 `work-results-before.json` 和 `work-results-after.json`。Work 夹具根据公开源码构造，不是用户真实 DOM。

新增 `layout-style-smoke.cjs` 以无扩展原生页面作基线，检查原生层初始加载与延后加载、长对话、展开项目列表、右侧面板开关、fixed/sticky 区域、用户底栏遮挡、滚动范围及启停恢复。只比较开关不足以发现层注册本身的副作用，必须保留无扩展对照。

0.1.4 新增 `dynamic-wireframe-smoke.cjs`，验证双图解码、不同动画相位、真实时间推进、设置联动、媒体切换清理、资源失败与几何/交互。动画相位抽样和真实时间推进是不同证据：不能把设置 `currentTime` 得到的截图单独解释为循环已自然播放。当前 headless 环境切换标签没有产生真实 `hidden` 状态，暂停检查通过父页可见性协议模拟；`pagehide` / `pageshow` 使用合成 `persisted` 事件覆盖清理与恢复，不能据此断言真实 BFCache 命中。

浏览器脚本将离线夹具响应到匹配地址，其他远程请求记录或阻断。当前发布结果见 `验证记录-0.1.5.md`；分享目录保留本次验证，历史修订见根目录 `CHANGELOG.md`。历史报告使用明确版本快照，不把最新共享输出当作冻结的历史证据。

测试使用新的独立 Chrome 用户资料目录，不操作用户现有浏览器资料。Chrome 新版本不支持旧的命令行直接加载流程时，脚本通过 Chromium 的扩展调试接口加载本机包。相关自动化机制见 [Puppeteer 官方扩展指南](https://pptr.dev/guides/chrome-extensions)。这只用于开发测试，用户安装仍采用 Chrome 的「加载已解压的扩展程序」。

测试截图必须标为「离线夹具中的实际扩展渲染」，与原先 AI 生成的静态设计图分开。以下事项需在真实登录页面进一步确认：

- 当前 ChatGPT 的侧栏、正文、输入框和设置弹层是否命中适配规则。
- 新会话、发送/停止、附件、复制代码、长回答滚动和会话切换完整行为。
- 账号差异、窄窗口、浏览器缩放以及其他网页扩展同时开启的影响。
- 自定义 MP4 的具体编码是否被该用户浏览器解码；WebM 测试不能代替所有 MP4 编码验证。

插件不需要模型额度运行。未来维护是否耗用模型额度取决于用户是否使用助手修改代码；没有安排任何自动调用模型或定期维护任务。

## 回归步骤

浏览器脚本需要 Node.js、Playwright 和本机 Chrome。交付包运行不需要这些依赖；开发测试可用环境变量 `NEBULA_PLAYWRIGHT_PATH` 指定 Playwright 模块、`NEBULA_CHROME_PATH` 指定 Chrome。具体参数以脚本开头注释为准。

先检查 manifest 和各脚本语法，再运行与变动相关的浏览器验证。网页样式修改应运行 Work 样式检查，并核对原有全套检查是否受到影响；设置或媒体修改应运行对应的原有回归。只有新修改、失败或尚未解决的问题需要重复检查。测试结果与截图可以更新，所以发布记录应保存明确版本的报告与测试范围。

真实网页发现差异时，保存准确截图、网页区域和扩展错误信息。0.1.1 的共享层顺序一经注册，皮肤开关无法在旧页撤销；升级到 0.1.2 必须重载扩展后整页刷新。保留原加载目录与标识，以沿用配置与本机素材。

## 发布

发布脚本：`../tools/build-release.ps1`。它只打包明确列出的运行文件，检查这些文件及 manifest 入口是否存在，生成带版本号的压缩包；不删除旧包，不包含测试用户资料。压缩包解压后 `manifest.json` 位于加载目录根部。源码工程保留测试、维护文档和设计图。

图片生成与使用记录见 `壁纸素材生成记录.md`。角色壁纸来自本项目成品设计图的无界面版本，不是把原 DSH 录屏嵌在网页后面。

0.1.3 的线框素材记录为 `线框蓝光素材生成记录.md`，0.1.4 的有色人物记录为 `人物双态素材生成记录-0.1.4.md`。发布后可运行 `tools/verify-release.ps1`，核对 ZIP 内运行文件与当前源码的哈希、版本和根部 manifest；核对报告保存为明确版本，不自动覆盖历史报告。双态人物没有增加权限或网络来源。
